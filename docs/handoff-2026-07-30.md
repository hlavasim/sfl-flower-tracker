## Conventions this repo expects

Unchanged from the previous handoff, plus four earned the hard way today:

- **`npm test | grep` exits 0 whether or not anything failed.** An `&& git push` chain after it
  will happily ship red — it did once today. Gate on the failure COUNT:
  `FAILED=$(npm test 2>&1 | grep -c "^not ok"); if [ "$FAILED" != "0" ]; then exit 1; fi`
- **Verify that a revert actually applied** before believing a red/green result. A scripted edit
  that silently no-ops (wrong line endings, an emoji stored as `\uXXXX`, bash eating quotes)
  leaves the suite green and reads as proof. Two near-misses today.
- **A/B on the live farm must run in ONE pass.** Two runs of identical code disagreed because a
  7-day shrine expired between them (Badger = trees+stone, Mole = iron/gold/crimstone, both
  speed 0.75). That artefact produced a 44-row "regression" table that did not exist, and
  earlier a phantom 0.5–0.8x engine divergence. Compare both sides inside one
  `page.evaluate`, not across two HTTP requests.
- **`powerState`, `ROADMAP_MINING_CATS` and every other top-level `const`/`let` in flowers.html
  are NOT on `window`.** Only `function` declarations are. Three diagnostics today reported
  nonsense (`46 mismatches`, `owned: 0`, `timed out`) because a probe read
  `window.powerState`. Reach the values through the global functions that close over them, or
  fetch them from the API.
- Measure UI fixes with `playwright-core` driving installed Edge
  (`chromium.launch({ channel: "msedge" })`) — no browser download, and it can override page
  functions at runtime for an A/B. Read `textContent`, not `innerText`: the latter is
  layout-dependent and returns "" for a hidden element.

## Status update — same day, later (through commit 6b7d818)

Everything below is deployed to production and verified there, not just locally.

### The unification is done: NODES computes nothing

The demand was "všechno přece má vycházet z jednoho místa". `nodeAcq` (section=ascension) is now
the only place node economics exist, and the NODES page renders it. Deleted from `flowers.html`:
`calcMarginalForProduct`, `getMarginalNetSfl`, `mergeEff`, `getNodeTiers`, `restockCostPerUnit`,
`PRODUCT_LISTS`, `NODE_FIXED_PRODUCTS`, `getRealRoi`, both `MERGE_COSTS` loops, and the page's own
dig-session efficiency pass.

The numbers moved, as agreed, and three of the moves are fixes:

- **Efficiency was applied twice.** The marginal already carried the ratio, then the table did
  `REAL = theo × eff` on top of it. Every "real" income and ROI on that page was scaled by eff².
- **Purchase prices escalated off the owned count.** The game reads
  `farmActivity["<Node> Bought"]`.
- **Buy Gold / Buy Crimstone were listed UNPROFITABLE** there while the roadmap and the ascension
  plan called them profitable — the reported bug. Buy Gold now reads +0.7114/day, 196 d ROI, and
  both pages print identical per-node figures.

Two more defects the rendered output exposed: CURRENT NODES printed `0.00` FLOWER for oil,
obsidian and flower beds (units/day now, with ⚠ where the resource sells but has no p2p price),
and the greedy plan's 50-step safety cap truncated silently (it says so now).

Served for this, each pinned: per-node `tiers` for all ten node types (not just the mergeable
four), `eff: {byCat, meta}`, `cat`, `buyRule`, merge `effRatio`, merge `coinSfl`, and `buy` at
depth 8. Two real bugs found while serving them: **merge `matSfl` was missing its coin half**
entirely, and the expand-vs-buy verdict was still being re-derived in the panel's render.

`NODE_PRICES`, `BASE_NODE_COUNTS`, `MERGE_COSTS` and `countNodeTiers` are now unused in
`flowers.html`. Left in place and marked with a comment, not deleted.

### Weather items: the reader was looking in the wrong place

"A wather items normálně mám, takže tam máš nějakou chybu" — correct. The game keeps placed
collectibles in **four** maps (`getCollectiblesAcrossLocations`): `collectibles`,
`home.collectibles`, `interior.ground.collectibles`, `interior.level_one.collectibles`. Both
readers checked only the first two, and on a current save **`home.collectibles` is empty** — the
house layout change moved everything to `interior.ground.collectibles`. A farm with all four items
placed reported all four missing. The dashboard card went from "4/4 MISSING" to "ALL 4 ACTIVE".

Three further things were wrong once the items could be found:

- placement requires `coordinates` (no coordinates = in the chest, per `placeCollectible.test.ts`);
- it requires `readyAt <= now` (still building protects nothing);
- the dashboard asked "is it placed?" and showed a green ✓ for a **spent** item — the trap in
  "vyprší ale zůstanou postavené tak na to pozor". `markWeatherCollectibleUsed` sets
  `used: true` and leaves it placed. Three states now, and the card names what is uncovered.

Renewal cost is no longer "unknown": `WEATHER_SHOP_ITEM_COSTS × getMultiplier(island)` (volcano
×2.5, desert ×2), which `renewWeatherCollectible.ts` charges with craft-time discounts
deliberately not applied. Priced through the same `_shrineIngredientCostSfl` the shrine rows use.
Coins stay in coins — this app treats them as free above 10k.
