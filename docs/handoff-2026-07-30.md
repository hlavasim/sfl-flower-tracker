## Conventions this repo expects

Unchanged from the previous handoff, plus four earned the hard way today:

- **`npm test | grep` exits 0 whether or not anything failed.** An `&& git push` chain after it
  will happily ship red — it did once today. Gate on the failure COUNT:
  `FAILED=$(npm test 2>&1 | grep -c "^not ok"); if [ "$FAILED" != "0" ]; then exit 1; fi`
- **Verify that a revert actually applied** before believing a red/green result. A scripted edit
  that silently no-ops (wrong line endings, an emoji stored as `\uXXXX`, bash eating quotes)
  leaves the suite green and reads as proof. Two near-misses today.
- **A/B on the live farm must run in ONE pass.** Two runs of identical code disagreed because a
  7-day shrine expired between them (Badger = trees+stone, Mole = iron/gold/crimstone, both
  speed 0.75). That artefact produced a 44-row "regression" table that did not exist, and
  earlier a phantom 0.5–0.8x engine divergence. Compare both sides inside one
  `page.evaluate`, not across two HTTP requests.
- **`powerState`, `ROADMAP_MINING_CATS` and every other top-level `const`/`let` in flowers.html
  are NOT on `window`.** Only `function` declarations are. Three diagnostics today reported
  nonsense (`46 mismatches`, `owned: 0`, `timed out`) because a probe read
  `window.powerState`. Reach the values through the global functions that close over them, or
  fetch them from the API.
- Measure UI fixes with `playwright-core` driving installed Edge
  (`chromium.launch({ channel: "msedge" })`) — no browser download, and it can override page
  functions at runtime for an A/B. Read `textContent`, not `innerText`: the latter is
  layout-dependent and returns "" for a hidden element.

   expand in `core/sections/ascension.mjs`; MERGE has its own path via `MERGE_COSTS` in
   flowers.html. Two paths — the exact shape that produced three separate bugs today. Measure
   both sides in one pass, then unify.
2. **Composters, and the whole fertiliser model.** `COMPOST_RECIPES` exists and `item-value.mjs`
   prices the outputs, but **what fertiliser DOES is modelled nowhere** — no rule treats Sprout

   effect table pulled from the GAME SOURCE (as `SKILL_POINTS_PER_TIER` and the node prices

   cycle and inputs), then the verdict.

## Facts worth not re-deriving

- Skill tier gates are per tree, from `SKILL_POINTS_PER_TIER` in the game's
  `events/landExpansion/choseSkill.ts`: Animals 4/8, Crops & Mining & Compost & Aging 3/7, the
  rest 2/5. **Points spent on tier-3 skills never count towards a gate**
  (`getUnlockedTierForTree` skips them).
- `bumpkin.skills` stores the current LEVEL as a number, not a presence flag.
- Node prices from `RESOURCE_NODE_PRICES` (`buyResource.ts`): Crop Plot 3/2, Tree 4/3, Stone 4/3,
  Fruit Patch 5/5, Iron 7/5, Gold 10/6, Crimstone 20/20, Flower Bed 30/25, Oil Reserve 40/20
  (desert-gated), Lava Pit 40/40 (volcano-gated). Escalation reads
  `farmActivity["<Node> Bought"]`, not the owned count.
- `farm.flowers` is a CONTAINER (`{flowerBeds, discovered}`), not a list of beds — counting it
  directly gives 2 where the farm has 4.
- 87 of the 153 skills have no Level 2/3 at all (Acre Farm and Hectare Farm among them).
- `roadmapEffFactor` can exceed 1 (gold 1.50 — the `ratio > 1.5` clamp in
  `roadmapComputeEfficiency` — trees 0.54). It is not a discount, it is a measured ratio.
- No flower has a price in the sfl.world p2p feed; only Sunflower and Cauliflower, which are
  crops.
- Frugal Miner and its kin discount the pickaxe's COIN price only, not the wood/stone/iron it is
  crafted from. `power-helpers` calls that variable `coinDiscount` for a reason; pricing the
  whole tool bill ran ~30x hot.
