## Conventions this repo expects

- `flowers.html` and `index.html` are byte-identical twins. `index.html` is what production
  serves. Deploy = `cp flowers.html index.html`, commit, `git push` (main auto-deploys on
  Vercel). Azure Functions do **not** deploy on push — they need
  `func azure functionapp publish`.
- Run `npm test` before every deploy. Current: **207/207**.
- A test that pins a bug must be shown to FAIL when the fix is reverted. Several bugs this
  session were only caught that way; a green suite proved nothing on its own.
- `core/` is a port of functions that also exist inline in `flowers.html`. **Both copies must
  be patched.** This bit twice today (see `unitToSfl`).
- `tests/core/constants.test.mjs` reads UPPER_SNAKE object/array literals in `flowers.html`
  as game-data tables and fails unless they are registered in `core/data/_inventory.mjs`.
  UI/render constants must therefore be lowerCamelCase (`nodeIconUrl`, `buyableNodes`).

## Open work, highest confidence first

### 1. Wishlist ROI for buds (and pets, which are counted within buds)

Real wiring bug, cause confirmed. `flowers.html` pushes bud rows onto `d.rows` **after** the
server response:

```js
d.rows.push({ key, name: bc.label, floor: bc.floor, ... })   // keys like "buds:<id>"
```

`buildWishlistSection` (`core/sections/wishlist.mjs`) only knows `collectibles` and
`wearables`, so it never sees them and `perDay` / `perDayEff` / `roiDays` / `roiDaysEff` are
undefined for every bud. The ROI column is not empty for buds, it is unreachable.

Fix direction: value bud boosts with `core/engine/buds.mjs` (exists) and put buds through the
same path as other rows — preferably by resolving `buds:` server-side so they stop being an
exception. Pets ride along, per the owner: "pets jsou počítány v buds".

### 2. Chicken / feed boosts value to zero

Not a modelling gap — I first reported that and was wrong (I looked up "Golden Egg"; the item
is **"Gold Egg"**). They are present and computed:

```
Gold Egg        chickens  synergy 0.000
Speed Chicken   chickens  synergy 0.000
Eggplant Onesie crops     synergy 0.000
```

`calcBoostValue` (`core/engine/roadmap.mjs:388`) has a `cost_reduction` branch, but it prices
savings on **tools** (`coinSavingsPerUse * baseCost.toolsPerDay`). Animal-feed savings do not
fit it and fall through to 0. Verify how feed savings parse into effects in
`core/engine/power-boosts.mjs` before changing anything — do not guess.

### 3. Wishlist column should distinguish "—" from "?"

Today a value of zero and a value we cannot compute both render `—`, which reads as
"worthless". Split them once #2 is understood.

### 4. WORLD activity filter jumps to the top of the page

Not fixed after three attempts, all deployed and measured. Node-type switching **is** fixed
(scroll 2186 → 2186, page rebuilt 0×, never blank) because it repaints only
`#world-node-panel`. The scope switch still measures 300 → 0.

Tried and insufficient: restoring scroll around each paint (`_worldKeepScroll`), forcing
layout with `body.offsetHeight` first, and capturing the offset on click to reapply after the
final paint over three frames. The scroller is `document.documentElement` — that was verified,
so the measurement is not the problem.

Likely direction: stop replacing `#app` wholesale on a scope change and repaint the individual
chart bodies, the way the node panel now does.

## Done this session (deployed, verified)

- **Non-sellable resources are not income.** Obsidian and oil cannot be sold
  (`TradeResource` in the game's `actions/tradeLimits.ts` excludes them; `SELLABLE` in
  `sellCrop.ts` is crops + fruit only). sfl.world publishes an Obsidian price (~20 FLOWER)
  and the code took it at face value: **103.3 FLOWER/day of unrealisable income, 36.8 % of a
  real farm's reported total**. Fixed in `unitToSfl` — core *and* the `flowers.html` copy.
  Live: 281.7 → 164.3 FLOWER/day. A test pins the two copies together.
- **Lava Pit** added to `NODE_PRICES` (it was missing, so the advisor never offered the one
  node that makes obsidian) and to the expand-vs-buy table, with its return in obsidian/day
  rather than a fictional FLOWER figure.
- **Ascension step ROI** now uses net, efficiency-adjusted income. On the live farm A1·e33
  went 14 → 34 days, A1·e39 61 → 195.
- **Pet boost consistency**: banked food was valued with the ×1.5 pet streak while the XP rate
  was not, inflating every level ETA (16.4 h vs the correct 10.9 h). Forced on in
  `compute.mjs` for the ascension section.
- **Bumpkin recipe selection** is now sent to `section=ascension`; without it the server rated
  all six kitchens and reported 930,913 XP/day instead of the farm's real 677,328.
- **World node-distribution chart** (`farm_world.node_tiers`, backfilled for all 656,470
  farms; `mode=nodes`), stacked into only-t1 / has-t2 / has-t3.
- **`world_agg`**: per-generation cache of each chart's response, computed on miss.
  `mode=nodes&node=trees` 26.0 s → **0.21 s**; whole table 43 kB.
- **Farm fetch cached in KV for 20 s** (`api/proxy.js`): a page load was rate-limiting itself
  into 502s. Load ~9 s with two 502s → 2.7–4.7 s, none.
- **Wishlist FLOWER/day + ROI** with a theoretical / measured-efficiency toggle, fed by POSTed
  farm-history snapshots.
- **WORLD shows the data's date** and age from `dump.generated_at`.
